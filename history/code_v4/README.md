# Native object-flow cost baseline

This is an isolated v4 flow runner. The v3 codec, decoder, VAE-cache and metric dependencies remain byte-identical. No GPU job was launched when preparing this snapshot. The experiment template remains unbound and cannot load a codec until root selects a gate-passed v3 checkpoint and supplies its exact SHA256.

`SmallObjectFlow` reuses `model.ObjectFlow`: width 384, depth 8, 6 attention heads, FF width 1536, full self-attention across 250 object tokens, cross-attention to the cached observed-prefix features, and one learned slot embedding per codec object. Each object latent has 128 values. The immutable codec anchor buffer binds slot order; it is not an extra positional feature. All **23,070,848** flow parameters are trained from random initialization. The final output projection starts at zero, so the first update reaches the output layer and subsequent updates reach hidden layers.

The frozen codec and its exact prefix `adapt_features()` route, future posterior target sampling, velocity flow-matching objective, noise/time generators, optimizer hyperparameters and 4/16-step × seeds17/29 evaluation are shared with the v3 Wan route. The small route loads no Wan or VAE weights and rejects Wan warmstarts or `--pretrained`. The v4 checkpoint format and positional extra state bind backend, architecture, dimensions and every slot's codec anchors. Resume and standalone eval reconstruct the recorded small dimensions and validate the full source/config/base/codec/data/cache protocol.

The small model's FP32 weights occupy 0.086 GiB; weights, gradients and Adam moments total about 0.344 GiB before activations, codec and renderer. Dense forward arithmetic is roughly 10 GFLOP per clip for 250 object tokens and a 128-token prefix. These are estimates, not GPU measurements or predicted speedups. Small kernels, Python/cache overhead and video rendering can dominate elapsed time. The runner reports actual step seconds, clips/s, training/evaluation/allocated GPU-hours and peak allocated/reserved bytes. Measure the admitted batch-8 path before interpreting its memory use.

This compares usable adaptation cost. It does not isolate a single architectural cause: small uses random full training and learned slot embeddings; Wan uses pretrained weights with trainable adapters/LoRA and its admitted positional policy. Only runs using the same exact v3 codec checkpoint can form this comparison. Existing A/v1 Wan runs use a different representation and remain separate practical baselines.

The paired ignored control templates are `flow_small_v3codec_s713_b8_15min.template.json` and `flow_wan_v3codec_s713_b8_15min.template.json`. Both set batch8, seed713, LR1e-4, pure flow matching, all train clips, native64 metrics, save every250 with 12 checkpoints retained, a 100000-update safety limit, and **0.25 hours accumulated training-loop time**. Evaluation time is reported separately. The hard wall-time cap is 0.5 hours including setup/evaluation, bounded again by 08:45. Small previews every1000 updates and Wan every250, so the faster learner is not mechanically penalized by preview frequency. Compare final endpoints at 900 training-loop seconds, not the best preview checkpoint; an earlier safety/wall/deadline stop reports `budget_outcome: partial`.

Both templates contain deliberately invalid checkpoint/SHA placeholders. Root must bind the same selected v3 checkpoint to both, rename final runs/configs as appropriate, and run the existing scoped resource launcher. No orchestration is automatic here. Resume retains the accumulated training seconds and the bound training budget; it does not restart a fresh 900-second allowance.

The final 32-clip evaluation runs only if budget remains; incomplete final evaluation is explicitly recorded. The regular fixed-showcase evaluation saves every seed, static persistence and separately labelled future-seen AE. A 15-minute pilot cannot establish semantic identity or physical compliance.

CPU checks use six module contract tests and a full CLI fixture: two updates, resume for a third, continuous three updates, exact model/optimizer/RNG comparison, and standalone all-seed rendering/metrics/GIF. An additional tiny-budget test stops after one completed update, resumes without consuming another update, and verifies that a wall cap before the training target is explicitly partial. The fixture has synthetic cache features and tests execution only. Test output lives outside source in ignored `code_v4_smoke/`.

Both flow implementations use internal CUDA BF16 autocast with FP32 master trainable weights. The outer `--no-amp` flag does not turn the flow itself into a full-FP32 CUDA experiment; the paired templates use the default enabled AMP policy.

Changed runtime files relative to v3: `codec_flow_research.py`; newly added runtime file: `small_object_flow.py`. `source_copy_manifest.json` records original v3 hashes; `checksums.json` records this snapshot's final files.
