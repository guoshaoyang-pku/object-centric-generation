# 当前 setting：以对象 latent 做条件视频生成

2026-10-27。本文描述**此刻代码里真实实现的东西**、它背后的原理，以及这项工作要检验的核心 idea。实现细节以 `slotformer-demo/research/20261027/snapshots/code_v4/`（C2 codec 与小对象 flow）和 `slotformer-demo/research/20261027_claude/joint_flow.py`（当前联合训练）为准。计划中但尚未实现的东西会明确标出。

## 一句话

把一段未来视频压缩成 **250 个带连续轨迹的“父候选”token**，在这个 token 集合上做 latent flow matching。给定前 4 帧，一次性生成整段未来 20 帧对应的全部 token，再用可微渲染器在任意 $(x,y,t)$ 上查询像素。

要检验的问题是：**在同样的数据与算力下，生成这种对象结构的 latent，是否比生成像素或规则网格 latent 更容易得到持续、少碎裂、交互合理的未来。** 压缩率和重建质量只是前提，不是答案。

## 1. 任务设定

| 项 | 当前取值 |
|---|---|
| 数据 | MOVi-E，9,749 段训练，250 段验证，128×128，24 帧，带纹理与相机运动 |
| 条件 | 前 4 帧（记作 $C$） |
| 目标 | 后 20 帧（记作 $Y$），**一次联合生成**，不是逐帧自回归 |
| 空间 | 二维画面加视频时间 $(x,y,t)$。不是三维重建，时间也不是深度 |
| 评测集合 | `cohorts_adopted.json`：showcase4（固定展示）、pilot32（固定 32 段验证）；采样 seed 17/29 全部保留 |

“一次联合生成”的含义：生成器输出一组 token，这组 token 定义了整段未来。第 15 帧画坏，不能归因于“第 14 帧的误差递归累积”，因为生成器从没有逐帧滚动。

## 2. 原理：这是一个 latent 生成模型，latent 是对象结构

整体框架与 latent diffusion 相同：先有一个自编码器，再在它的 latent 空间里学条件分布（[Rombach et al. 2022](https://arxiv.org/abs/2112.10752)）。区别只在 latent 的形状与解码方式：这里的 latent 不是规则图像 patch，而是一组父候选，解码器是显式的可微渲染器。

**编码（只在训练时看真实未来）**

$$z_0 = E(Y) \in \mathbb{R}^{250\times 128}$$

实际取后验采样 $z_0=\mu+\sigma\odot\xi$，不是后验均值。

**生成器：flow matching**（[Lipman et al. 2022](https://arxiv.org/abs/2210.02747)）

$$z_s = (1-s)\,\epsilon + s\,z_0,\qquad \epsilon\sim\mathcal N(0,I),\quad s\sim U[0,1]$$

$$L_{\mathrm{FM}} = \big\| v_\theta(z_s, s, C) - (z_0-\epsilon) \big\|^2$$

**采样与解码**

从 $\epsilon$ 出发，用 16 步 Euler 积分 $s:0\to1$ 得到 $\hat z_0$，再解码渲染：

$$\hat Y(x,y,t) = R\big(D(\hat z_0);\,x,y,t\big)$$

两个“时间”必须分开：

- **$s$ 是去噪进度**。16 步 Euler 是 $s$ 的积分步，不是视频的 16 帧。
- **$t$ 是视频时间**。它只出现在渲染查询 $(x,y,t)$ 里。

同一个 $\hat z_0$ 被查询 20 次，得到 20 帧。GIF 里看到的“化开、碎裂”是最终视频的失败模式，不是“还在去噪中”。

另外两点：

- 中间的 $z_s$ 不需要是合法对象，也不需要符合物理。只有最终 $\hat z_0$ 解码后才要求几何与运动合理。
- latent 上加的高斯噪声 $\epsilon$，与渲染器里的 Gaussian 子核是两回事。

## 3. 表示：一个 token 解码成什么

### 3.1 编码器 $E$（后验，约 1.0M 参数）

1. 冻结的 Wan2.2 VAE（704.7M 参数）把未来 20 帧（补到 21 帧）编码为 384×48 的特征，离线缓存。
2. 两层小 MLP（48→256→256）加上 $(x,y,t)$ 位置特征，得到 384 个特征 token。这个 MLP 也被前缀条件路径共用。
3. 250 个可学习 query，**做一次** cross-attention 读取这些 token。注意力带有高斯空间偏置：第 $k$ 个 query 偏向读取靠近其 anchor $a_k$ 的特征（$\sigma_x=0.4,\ \sigma_y=0.5$，坐标归一化到 $[-1,1]$）。
4. 输出均值 $\mu$（每个 token 做 LayerNorm）与对数方差。训练时用采样 $z=\mu+\sigma\odot\xi$，KL 权重 $10^{-5}$。

这个编码器很浅，已有证据表明它是瓶颈（见第 6 节）。

### 3.2 解码器 $D$：每个 token → 一个“父候选”（parent）

一个共享 MLP（128→256→256→806）把每个 token 独立解码成 806 个字段：

| 部分 | 字段数 | 含义 |
|---|---:|---|
| 中心轨迹 | 2 + 6 | 立方 Bezier 曲线 $c(t)$，$c_0 = a_k + \tanh(\cdot)$，其余三个控制点是相对偏移 |
| 仿射 | 4 + 4 | $A(t)=R(\theta)\,\mathrm{diag}(e^{\ell_x},e^{\ell_y})\,\mathrm{shear}(h)$，四个系数随 $t$ 线性变化 |
| 子核 | 6×4 | 4 个局部椭圆 Gaussian（中心、尺度、角度、相对幅度）。幅度经 log-softmax，只决定父候选内部的分配 |
| 基础颜色 | 3 | RGB logit |
| 纹理 | 7×109 | 109 个局部 RBF，各有中心、尺度和 RGB 残差 |

几何 43 + 纹理 763 = 806 字段，每段视频共解码 201,500 个数，而 latent 只有 32,000 个数。codec 网络权重共 1,304,358，其中编码器 998,400，解码器 305,958。

**所有子核和纹理都定义在父候选的移动局部坐标里**：$\ell = A(t)^{-1}\big((x,y)-c(t)\big)$。整个父候选随同一条轨迹与仿射一起移动，这就是“共享运动”。

### 3.3 渲染器 $R$：归一化密度混色

对查询点 $(x,y,t)$：

$$\rho_k = \log\sum_{j}\exp\!\Big(-\tfrac12\|\ell_{kj}\|^2 + \alpha_{kj}\Big),\qquad w_k = \mathrm{softmax}_k(\rho_k)$$

$$\mathrm{RGB}(x,y,t) = \sum_k w_k\;\sigma\big(\mathrm{color}_k + \mathrm{texture}_k(\ell_k)\big)$$

由此得到这个表示几条**容易被误读的性质**：

1. **背景也由父候选表示**。混色权重在每个像素上归一化，所以每个像素都被某些父候选染色。250 个父候选不仅描述前景物体，也铺满了地面和墙。
2. **没有深度顺序与 alpha 遮挡**。下标不是图层。两个父候选重叠时按密度比例混色，而不是前者盖住后者。
3. **父候选覆盖整个 $t$ 区间**，没有出生/死亡开关。物体出画、被遮挡、新入画，都只能靠移动或被别的父候选的密度压过来表达。
4. **子核幅度经 log-softmax**，因此单个父候选不能靠幅度把自己整体“调没”。它只能靠缩小尺度，或被其他父候选的密度压过，才在画面上消失。

### 3.4 对称性：这里的“对象”被空间锚定

对象集合本应对排列不变：交换两个 token，视频可以完全相同。当前实现用三处设计**刻意打破**了这个对称：

- 250 个 anchor $a_k$ 取自 $[-0.9,0.9]^2$ 上 16×16 固定 xy 网格的前 250 个点；
- 后验 query 的注意力被 anchor 附近的特征吸引；
- flow 的每个槽位有可学习的 slot embedding，槽位编号对生成器有意义。

所以第 $k$ 个 token 的含义大致是“**起始在 anchor $k$ 附近、可变形可移动的一块区域**”。它更接近一张持续存在、可以变形的网格，而不是语义实例。这个选择回避了集合匹配问题，代价是语义归属：一个真实移动物体平均对应约 23.5 个有效父候选。

## 4. 生成器：小型全局对象 flow

| 项 | 取值 |
|---|---|
| 结构 | 8 层，宽 384，6 头；每层为 250 个 token 的全局 self-attention，加上对前缀 token 的 cross-attention，再接 FFN；时间 $s$ 的嵌入作为偏置，加到每个子层 LayerNorm 之后；输出层零初始化 |
| 输入 | $z_s$ 线性投影，加 slot embedding |
| 条件 | 前 4 帧 → 冻结 Wan VAE → 128×48 → codec 的小 MLP（与编码器共享）→ 128×256 → 线性投影 |
| 参数 | 23,070,848 可训练，随机初始化，未继承 Wan DiT |
| 掩码 | 没有逐帧 causal mask。所有未来 token 每一步都相互可见 |

250×250 的注意力矩阵只有 62,500 项。当前不需要局部注意力，对象之间的交互通过全局注意力建模。

**泄漏边界**：采样路径只调用前缀条件与 flow，不调用编码器。真实未来只在训练时用于构造 $z_0$ 和 RGB 标签。

## 5. 训练路线：先 AE，再冻结 flow，再联合

| 阶段 | 训练什么 | 损失 | 状态 |
|---|---|---|---|
| 1. 对象 AE | C2 codec（编码器 + 解码器） | 采样 query 的 RGB MSE + $10^{-5}$ KL | 完成，100k 更新，0.747 H200h |
| 2. 冻结 codec 的 flow | 小对象 flow | 仅 $L_{\mathrm{FM}}$，$z_0$ 为后验采样并 `detach` | 完成，27,362 更新，0.25 H200h |
| 3. 联合 | flow + codec | 见下式 | **正在运行**（2026-10-27 17:50 起） |

阶段 3 的损失：

$$L = L_{\mathrm{FM}} + \lambda_{AE}\,L_{AE} + \lambda_{m}\,L_{\mathrm{match}} + 10^{-5}\,\mathrm{KL}$$

- $L_{AE}$：真实未来 → $E$ → $D$ → $R$，在每段 512 个随机未来 query 上与真实 RGB 做 MSE。梯度到编码器与解码器。
- $L_{\mathrm{match}}$：$\hat z_0 = z_s + (1-s)\,v_\theta$，渲染同一批 query，按 $s$ 加权的 MSE。梯度到 flow 与解码器，**不到编码器**。
- $L_{\mathrm{FM}}$ 的目标 $z_0$ 仍然 `detach`。编码器学习率 $10^{-6}$，解码器 $10^{-5}$，flow $10^{-4}$。

三个 run 从同一个 checkpoint（27,362 步，含优化器与 RNG）出发，数据流相同，各占一张 H200：

| run | 设置 | 目的 |
|---|---|---|
| `control_frozen_10h` | 冻结 codec，只有 $L_{\mathrm{FM}}$，训练到累计 10 h | “只是训练更久”能带来多少 |
| `abl_joint_nomatch_10h` | 联合，$\lambda_m=0$，训练到 10 h | 只让 codec 跟着训练（$L_{AE}$）的效果 |
| `main_joint_60h` | 联合，$\lambda_m=1$，训练到 10 h（原计划 59.5 h，19:00 截短） | 与上两臂在 10 h 同预算比较 |

**19:00 起的集中 run**：1 h 里程碑上，冻结 codec 的生成明显优于两个联合臂（pilot32 sample-16 MSE 0.0113 对 0.0123–0.0126，运动 cosine 0.087 对 0.064–0.072），且从 0.25 h 到 1 h 仍在快速改善。生成误差约为 AE 下限的 3 倍，瓶颈在 flow。因此剩余算力集中到冻结 codec flow：

| run | 设置 |
|---|---|
| `frozen_ddp_main` | 从 `control_frozen_10h` 的 1 h checkpoint 分支；2 卡 DDP，global batch 64，LR $10^{-4}$，EMA 0.9999（报告模型）；训练到累计 55 GPU 时 |

它与 10 h 对照的差异同时包含 batch、EMA 与卡数，只能作为“扩大配方”的结果。该 run 之后在约 2.4 GPU 时发散并已停止，见 README 的“第一轮的四个 run 全部发散”。实时状态和决策记录保存在原项目的实验控制目录里，不随本仓库发布。

## 6. 三个结构性风险，以及我们手上的证据

### 6.1 重建容易的表示，不一定是生成容易的表示

重建只要求 $D(E(Y))\approx Y$。编码器可以把相似视频编码到很远的位置，把同一物体分给不同槽位，或者把运动藏进纹理变化。解码器能还原，重建损失就不会反对；但这些不规律会让生成更难。

已有证据：

- **编码器没有找到好的 latent**。固定解码器，用真实未来直接优化 $z$，4 段展示的 native128 MSE 从 0.003313 降到 0.000970（−70.7%）。解码器能表达得更好，是编码器没有找到。
- **身份碎片化**。一个有明显移动的真实实例，平均对应约 23.5 个有效父候选。

只看重建质量不足以判断 AE 好坏，还应检查：

1. 同一视频内实体的身份是否稳定；
2. 相近的外观或运动是否对应有规律的 latent 变化；
3. 对 latent 加小扰动，解码是否平稳；
4. 同样的生成器预算下，对象 latent 是否比网格 latent 更容易预测。

第 4 项才是本工作的研究价值所在。

### 6.2 对象是集合，patch 是网格

patch token 的位置有固定含义，对象槽位的编号通常没有。当前实现用空间锚定回避了这个问题（第 3.4 节）。这让 flow 可以使用 slot embedding，代价是槽位接近“区域”而非“实体”。

替代方案有两种：排列等变的对象网络，或者稳定的对象分配。不需要让第 7 个槽位在所有视频里都是杯子；需要的是，同一段运动里身份不要无规律地跳槽。这属于新架构的选择，当前实验没有改动它。

### 6.3 生成后的 RGB 监督，与唯一真实未来之间的错配

假设同一个前缀之后，球既可能向左也可能向右：

- **正确的生成目标**：不同噪声产生不同的合理未来。
- **从独立噪声积分到底，再与唯一的真实未来逐像素比较**：每个噪声都被要求解释同一条样本，整体上奖励平均结果，也就是模糊。

当前代码**不使用**这种 rollout RGB 损失。$L_{\mathrm{match}}$ 的输入 $z_s$ 由真实 $z_0$ 加噪构成，属于 target-conditioned 去噪，与标准去噪训练同类。但它仍有一个细微问题：在 $s$ 小时，$\hat z_0$ 接近条件均值，$L_{\mathrm{match}}$ 等于要求“渲染出的条件均值”贴近真值。由于渲染器非线性，$R(D(\mathbb E[z]))\neq \mathbb E[R(D(z))]$，这会推动解码器去迁就均值 latent。按 $s$ 加权削弱了小 $s$ 段，但没有消除这个问题。`abl_joint_nomatch_10h` 正是为了单独量出这一项的作用。

### 6.4 联合训练会移动生成目标

`stop-gradient` 只隔断当次反传，不能阻止编码器更新后 $z_0$ 的分布漂移。实测：编码器学习率 $10^{-5}$ 时，583 步内 showcase 上 $\mu$ 的相对偏移达 6–9%，且只用 4 段训练时，验证集 future-AE 变差。改为 $10^{-6}$ 后，300 步内偏移约 1%。每次 quick eval 都会记录这个偏移量。

## 7. 现有结果说明了什么，没说明什么

冻结 codec、每个生成器新增 0.25 H200h 训练、pilot32、16 步、native128、双 seed 平均：

| 方法 | RGB MSE↓ | 前景 MSE↓ | 运动差分 cosine↑ |
|---|---:|---:|---:|
| 重复最后一帧 | 0.021402 | 0.036928 | — |
| 全局相似变换外推（零训练） | 0.017764 | 0.032219 | **0.08699** |
| 小对象 flow | **0.013932** | **0.030256** | 0.03765 |
| 小 VAE-patch flow | 0.018060 | 0.037803 | 0.02094 |
| Wan 对象适配 | 0.029204 | 0.057491 | 0.00097 |

在共同 64px 口径下，真正的 raw-pixel flow 为 0.025795，对象 flow 为 0.012484。

**能说的**：

- 这套对象 latent 可以被一个 23M 的随机初始化 flow 学到可用的程度；
- 在相同的小预算下，它的 MSE 低于网格 latent 与原始像素；
- 生成器在少量训练条件上能逼近 codec 自身的重建（4 段记忆实验：生成 0.005050，AE 0.004971）。

**不能说的**：

- **物理优势**。在共同 64px 口径下，把静止续写做 σ=2 的空间低通，前景 MSE 为 0.025753，略低于对象 flow 的 0.026455，配对差异区间跨零。MSE 优势有一部分来自模糊。
- **更好的运动**。运动方向 cosine 低于零训练的全局外推。
- **语义对象**。父候选不是语义实例，身份仍然碎裂。
- **泛化**。只有一个训练 seed；showcase 与 pilot32 都是被反复看过的开发验证集。
- 增加 Euler 步数（16→64→128）没有修复固定展示案例。

## 8. 评测口径（避免混淆）

| 口径 | 看到真实未来？ | 用来回答 |
|---|---|---|
| future-AE | 是 | 表示的重建上界 |
| 训练集记忆 | 训练样本 | 管线能否拟合，不是泛化 |
| 前缀生成（验证集） | 否 | 真正的续写能力 |

还有几条约定：

- 负对照：静止续写、全局相似变换外推、固定空间低通。
- 汇总方式：按 clip 配对汇总与 bootstrap，不把像素当独立样本。
- 分辨率：native128 与“直接 64 查询”是两种口径，不能混在一条曲线里。
- 高清渲染只是更密的查询，不等于学会了更多细节。时间加密不等于预测了更长的未来。

## 9. 核心 idea 为什么可能成立

下面是这项工作押注的机制，**都还没有被证实**：

1. **持续性写进了表示**。一个父候选在整个 $t$ 区间存在，并沿一条连续轨迹移动。“物体凭空消失”需要表示主动去隐藏它；而在像素或 patch 空间，消失只是一组像素变得和背景一样。
2. **运动是少量连续参数**。一个父候选的运动由 8 个轨迹数和 8 个仿射数描述，生成器预测的是这些参数的联合分布，而不是 20 帧中逐块的外观变化。
3. **交互落在 token 之间**。理想情况下一个 token 对应一个实体，“谁碰到谁”就是两个 token 之间的关系；在网格 latent 中，一个物体分散在多个 patch 里，一次碰撞要求多块 patch 协同变化。当前约 23.5 个父候选共同表示一个实例，这个优势还没有兑现。
4. **token 数与像素数解耦**。同一组 token 可以在任意分辨率、任意帧时刻查询，生成成本不随输出像素增加。

当前实现对这些机制的支持并不完整：没有遮挡顺序、没有出生/死亡、轨迹是全局三次曲线（难以表达碰撞后的速度突变）、槽位被空间锚定而不是语义绑定。所以，现阶段的结果只能检验“可变形持续网格 + 全局交互”这一弱化版本，还没有检验完整的“对象”假设。

## 10. 尚未回答、值得讨论的问题

- **成功的标准**：同等预算下，对象 latent 在哪些指标上优于网格 latent 才算支持核心 idea？建议至少包括碎裂/消失率、身份稳定性、接触前后的速度一致性，而不只是 MSE。
- **物理证据从哪来**：需要固定相机、有明确接触/碰撞的数据与对应的物理指标。MOVi-E 的相机运动会把投影运动与物理速度混在一起。
- **表示是否“好生成”**：可以直接测 latent 的平滑性与可预测性（第 6.1 节的 1–3 项），不必等生成结果。
- **锚定还是语义**：继续用空间锚定（容易训练、身份碎），还是换成排列等变或匹配式分配（身份可能更好、训练更难）？
