# Roadmap

以下都是**计划，尚未执行**。来源：2026-10-27 实验记录中的下一轮计划 B 与 D，以及 [`current-setting-2026-10-27.md`](current-setting-2026-10-27.md) §10。启动任何一项之前，先等 2026-10-27 这一轮实验的最终报告，再与新架构的讨论一起确定先后顺序。

## Long video（计划 D）

MOVi-E 每段固定 24 帧（2 s），本身无法检验长程一致性。

**D1：latent 自回归续写（便宜，先做）**

- 把生成的最后 4 帧重新经冻结 Wan VAE 编码成前缀，续写多段，例如 4+20×4。
- 指标：物体消失或碎裂率、parent 身份在段与段之间的保持、颜色与亮度漂移。
- 没有真实未来可比，只做定性和自洽性指标。推理时需要加载 VAE 编码器。

**D2：换成长视频数据（主线候选）**

- 固定相机、带明确碰撞的长视频，例如 CLEVRER（每段 128 帧）。这同时回应 §10 里“物理证据从哪来”的问题。
- 代价：新的不可变数据快照、VAE 缓存、codec 预热；token 预算和整段三次 Bézier 轨迹都要改，比如改成分段轨迹，或在 latent 里按段递推并带上 parent 身份。属于架构改动，要先讨论。

顺序：先用 D1 量出现有表示在长程上怎么坏，再决定 D2 的架构。

## Resolution（计划 B）

动机：对象 latent 固定为 250×128 = 32,000 个数。

| 分辨率 | 未来 20 帧像素值 | Wan VAE latent | 对象 latent |
|---|---:|---:|---:|
| 128 | 983,040 | 18,432 | 32,000（Wan latent 的 1.74 倍） |
| 256 | 3,932,160 | 73,728 | 32,000（Wan latent 的 0.43） |

“token 数与分辨率无关”要到 256 及以上才体现得出。另外，Wan VAE 空间压缩 16 倍，128 下每个 latent 帧只有 8×8 个特征，250 个 parent 只能从每帧 64 个位置读信息，而 MOVi-E 每段只有 1–3 个动态物体，常常小于一个 token。

注意：当前瓶颈是 flow 的运动预测，分辨率只是对输入端的一个假设，不针对已知瓶颈。

**B1：128→256 上采样输入（先做）**

- 把 128 RGB 双线性上采样到 256 再送进冻结 Wan VAE。信息量不变，只把 VAE 网格变成每帧 16×16。问的是：更细的输入网格本身，能否帮助编码器定位、帮助 flow 读出前缀运动。
- 改动：新建 VAE 缓存（另放、另记 manifest/hash）；编码器和 flow 的前缀 cross-attention 改读新 token 数。解码器、渲染器和 250×128 latent 都不变。
- 对照：同一流程跑一个 128 臂（同样的 codec 预热步数、flow GPU 时、seed 和数据顺序），不拿旧 run 当对照。
- 报告：pilot32 的 future-AE、sample-16/4 MSE、运动 cosine，seed 17/29；64px 与 128px 查询各报一次；重建、训练记忆与 heldout 生成分开报告。
- 判断规则（启动前固定）：在相同 flow GPU 时下，两个采样 seed 都优于 128 臂，且差距超过 128 臂两个 seed 之差，才算“有帮助”。

**B2：真 256 数据（视条件而定）**

- 启动条件：B1 有帮助，或者 flow 的生成误差已接近 AE 下限、codec 成了瓶颈。两条都不满足就不做。
- 数据：Kubric 官方 MOVi-E 的 256 配置（原生最高分辨率），同样 9,749/250 划分。完整 TFRecord 约 280 GB，其中 RGB 只占约 10%；只取 `video` 和 `segmentations` 约 28 GB。
- 风险：256 的纹理细节可能超出当前 Gaussian 加 RBF 的表达能力，像素 MSE 的 AE 下限可能变差。这要与运动指标分开报告。

## Open Questions（setting 文档 §10）

- **成功的标准**：同等预算下，对象 latent 在哪些指标上优于网格 latent 才算支持核心 idea？建议至少包括碎裂/消失率、身份稳定性、接触前后的速度一致性，而不只是 MSE。
- **物理证据从哪来**：需要固定相机、有明确接触/碰撞的数据与对应的物理指标。MOVi-E 的相机运动会把投影运动与物理速度混在一起。
- **表示是否“好生成”**：直接测 latent 的平滑性与可预测性，不必等生成结果。
- **锚定还是语义**：继续用空间锚定（容易训练、身份碎），还是换成排列等变或匹配式分配（身份可能更好、训练更难）？
- **遮挡与出入画**：是否引入深度序或显式可见性变量？这会改变渲染器，属于新架构。
- **联合训练的形态**：慢编码器、EMA 目标，还是交替更新？第一轮的三臂对比因发散没能完成。
